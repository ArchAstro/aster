  <action>
1. Create `src/executor/logs.rs`:
   - `RunLog` struct (Serialize, Deserialize):
     - `timestamp: String` (ISO 8601)
     - `target: String` (e.g., "test")
     - `results: Vec<TargetLog>`
   - `TargetLog` struct (Serialize, Deserialize):
     - `address: String` (e.g., "//services/api:test")
     - `status: String` ("passed", "failed", "skipped")
     - `exit_code: Option<i32>`
     - `duration_ms: u128`
     - `output: String` (full stdout+stderr)
   - `LogStore` struct:
     - `log_dir: PathBuf` (.aster/logs/)
   - `impl LogStore`:
     - `fn new(workspace_root: &Path) -> Self`:
       - log_dir = workspace_root.join(".aster").join("logs")
     - `fn store(&self, run: &RunLog) -> anyhow::Result<()>`:
       - Create log_dir if needed
       - Write to log_dir.join("latest.json") (overwrites previous)
       - Use serde_json::to_string_pretty
     - `fn load_latest(&self) -> anyhow::Result<Option<RunLog>>`:
       - Read latest.json if exists, return None if not
     - `fn get_target_log(&self, address: &str) -> anyhow::Result<Option<TargetLog>>`:
       - Load latest, find matching target by address

2. Update `src/executor/mod.rs`:
   - Export logs module
   - Re-export LogStore, RunLog, TargetLog

<task type="auto">
  <name>Task 3: Integrate progress display and log storage into executor</name>
  <files>
    - src/executor/runner.rs
    - src/main.rs
  </files>
  <action>
1. Update `src/executor/runner.rs`:
   - Add `use crate::ui::ProgressDisplay;`
   - Add `use crate::executor::logs::{LogStore, RunLog, TargetLog};`
   - Modify `Executor::execute()` signature to accept `output_mode: OutputMode`
   - Add `ProgressDisplay` to executor flow:
     - Create ProgressDisplay at start (enabled = output_mode == Normal)
     - Before running each target: `progress.add_running(address)`
     - Periodically update message with last output lines (during execution)
     - After completion: `progress.mark_complete(address, success, skipped, duration_ms)`
   - After all execution completes:
     - Build RunLog from results
     - Store via LogStore (only in Normal mode, not Json/Quiet)

2. Add failure presentation after execution:
   - For each failed target:
     - Print blank line
     - Print "FAILED //project:target" in red
     - Print exit code if available
     - Print last 10-15 lines of output (indented)
     - Print hint: "Run `aster logs //project:target` for full output" (dimmed)
   - Only in Normal and Verbose modes (not Json or Quiet)

3. Update `src/main.rs`:
   - Pass `cli.output_mode()` to executor.execute()
   - In Affected command: same pattern

4. Handle output interleaving in verbose mode:
   - In Verbose mode, prefix each output line with project address
   - Or buffer per-project and flush on completion (simpler)
   - Choose buffered approach: collect output, print with header when done

Note: The progress display should only show when:
- Output mode is Normal
- stdout is a terminal (use std::io::IsTerminal)
If not a terminal, fall back to simpler line-by-line output.
  </action>

    - `aster test --json` does NOT show progress (stdout stays clean)
