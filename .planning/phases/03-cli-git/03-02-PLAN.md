  <action>
Create the git module for detecting changed files:

1. Add git2 dependency to `Cargo.toml`:
   ```toml
   git2 = "0.19"
   ```

2. Create `src/git/mod.rs`:
   - Export affected module

3. Create `src/git/affected.rs`:
   - `AffectedDetector` struct holding reference to git2::Repository
   - `AffectedDetector::new(workspace_root: &Path) -> Result<Self>`:
     - Use Repository::discover() to find .git
     - Return error if not in a git repo
   - `changed_files_between_refs(&self, base: &str, head: &str) -> Result<HashSet<PathBuf>>`:
     - Use repo.revparse_single() for both refs
     - Use repo.diff_tree_to_tree() to get diff
     - Collect all changed file paths from diff deltas (both old and new paths)
   - `uncommitted_changes(&self) -> Result<HashSet<PathBuf>>`:
     - Use repo.statuses() with StatusOptions
     - Include untracked files
     - Collect paths from status entries
   - `all_affected_files(&self, base: &str, head: Option<&str>) -> Result<HashSet<PathBuf>>`:
     - If head provided: only compare refs (no uncommitted)
     - If head None: compare base..HEAD plus uncommitted changes
     - This matches Nx default behavior

4. Add to `src/lib.rs`:
   - `pub mod git;`
   - Re-export AffectedDetector

Handle ref fallback: If base ref doesn't exist, try common alternatives:
- "main" -> "master" -> "origin/main" -> "origin/master"
Or just let the error propagate with a clear message like "ref 'main' not found".
  </action>
  <verify>
cargo build compiles with git2
cargo test git passes
  </verify>
  <done>
AffectedDetector can detect changed files between git refs and uncommitted changes.
  </done>

<task type="auto">
  <name>Task 2: Implement file-to-project mapping</name>
  <files>
    src/git/file_owner.rs
    src/git/mod.rs
  </files>
  <action>
Create file-to-project ownership mapping:

1. Create `src/git/file_owner.rs`:
   - `files_to_projects<'a>(changed_files: &HashSet<PathBuf>, projects: &'a [DiscoveredProject]) -> HashSet<String>`:
     - For each changed file, find which project owns it
     - A project owns a file if the file path starts with project's relative_path
     - Sort projects by path length (longest first) to match most specific project
     - Return set of affected project addresses
   - `affected_with_dependents(directly_affected: HashSet<String>, graph: &ProjectGraph) -> HashSet<String>`:
     - BFS to find all projects that depend on affected projects
     - Use graph.dependents() method added in Plan 01
     - Return union of directly affected + all their dependents

2. Update `src/git/mod.rs`:
   - Add `pub mod file_owner;`
   - Re-export file_owner functions

Important: File paths from git are relative to repo root. Project relative_path is also relative to workspace root. These should match directly.

Edge case: Files in workspace root that don't belong to any project (like README.md, .gitignore) should be ignored (no project owns them).
  </action>
  <verify>
cargo test file_owner passes
  </verify>
  <done>
Changed files can be mapped to their owning projects, with transitive dependents included.
  </done>
</task>

Complete the affected command integration:

1. Update `src/cli/commands.rs`:
   - Add `Affected` subcommand:
     ```rust
     Affected {
         /// Target to run (test, build, lint, etc.)
         target: String,

         /// Base ref for comparison (default: main)
         #[arg(long, default_value = "main")]
         base: String,

         /// Head ref for comparison (default: HEAD + uncommitted)
         #[arg(long)]
         head: Option<String>,

         /// Also run dependents of affected projects
         #[arg(long)]
         dependents: bool,
     }
     ```

2. Update `src/main.rs`:
   - Handle `Commands::Affected { target, base, head, dependents }`:
     - Create AffectedDetector from workspace_root
     - If not in git repo, error with clear message
     - Call all_affected_files(base, head)
     - Map files to projects via files_to_projects()
     - If dependents flag, expand with affected_with_dependents()
     - If no projects affected, print "No projects affected" and exit success
     - Otherwise, call Executor with affected projects
   - Use the same execution logic from Run command

   - Test file_owner mapping logic with mock data
   - Test that affected command errors gracefully when not in git repo

Error handling:
- Not in git repo: "Not in a git repository. The 'affected' command requires git."
- Ref not found: "Git ref 'xyz' not found. Check your --base/--head values."
